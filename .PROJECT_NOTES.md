# Release_A1 Проект — Справка

## Описание
**БУХЛОЧАТ** — официальный хаб для встреч, событий и общих выездов. Это клиентское JS-приложение с простой авторизацией, админ-кабинетом и таймером до поездки на Нёман.

## Стек
- Язык: JavaScript, HTML, CSS
- Архитектура: vanilla JS, static site, Supabase shared data with localStorage cache
- Дополнительно: Supabase REST/Auth для общей базы данных; JSON-файлы остаются fallback и резервным импортом

## Последние обновления
- Дни рождения и праздники загружаются из Supabase и кэшируются в `localStorage`; JSON используется как fallback/импорт
- Подключённая Supabase-база перепроверена через публичный REST API: доступны `public.events`, `public.birthdays`, `public.holidays`; публичный запрос к `events` сейчас возвращает пустой список
- У `public.events` по диаграмме есть `id`, `created_at`, `title`, `location`, `description`, `recurrence`, `date`; `time`, `"maxParticipants"` и `event_id` добавляет `supabase/schema.sql`. Клиент (`js/supabase.js`) работает с таблицей `events` и ключом `event_id`
- Проверка доступа реализована на клиенте; значения в JavaScript доступны посетителям и не являются защитой для секретов
- Исправлен `data/birthdays.json`: теперь данные обёрнуты в объект `{"birthdays": [...]}` с полями `date` (YYYY-MM-DD) и `name` — `loadBirthdays()` в `js/main.js` корректно читает и отображает дни рождения
- В день рождения по списку запускается кратковременная анимация падающих шариков и лент; эффект отключён при `prefers-reduced-motion`
- В блоке «Галерея выездов» отображается фотография `gallery/Lida.jpg`; изображение адаптивно подстраивается под ширину карточки
- Прошедшие события скрываются после завершения календарного дня; все события (разовые и `recurrence: "yearly"`) показываются на главной с календарной даты за месяц до годовщины и скрываются со следующего дня
- Таймер до Нёмана обновлён и оформлен как крупный neon-style countdown
- Основной стиль страницы обновлён: более чистый dark UI, акцентные цвета, glow-эффекты, улучшенные карточки и кнопки
- Авторизационный экран разделён визуально и выглядит как отдельный входной блок

## Основные сценарии

### Главная страница (`index.html`)
- блок `auth-overlay` с контрольным вопросом и входом в хаб
- опция «Запомнить меня на этом устройстве» сохраняет доступ в браузере через `buhlo_hub_authenticated`
- доступ на главный контент только после корректного ответа `Лена`
- фото `gallery/Lida.jpg` отображается в блоке «Галерея выездов»; новые фото нужно положить в `gallery/` и указать путь в HTML
- меню разделов: события, таймер, встречи, алкометр, контакты, дни рождения
- загрузка `js/main.js` на старте

### Логика главной (`js/main.js`)
- `HUB_ANSWER = 'лена'` — корректный ответ для входа в хаб
- `EVENTS_KEY = 'buhlo_events_data'` — ключ событий в localStorage
- `REGISTRATIONS_KEY = 'buhlo_registrations'` — ключ регистраций на события
- `checkAuth()` — проверка входа в хаб
- `initPage()` — инициализация таймера, калькулятора и событий
- `startTimer()` — обратный отсчет до даты `buhlo_target_date`
- `calculateAlcohol()` — расчет закупки алкоголя
- `loadEvents()` — загрузка из Supabase, затем fallback на `data/events.json` и localStorage
- `loadBirthdays()` — загрузка из Supabase с fallback на JSON, отображение в `bdays-sec` и праздничная анимация
- `submitRegistration(eventId)` — регистрация на событие

### Админка (`pages/admin.html` + `js/admin.js`)
- вход администратора выполняется через Supabase Auth; токен страницы хранится только в памяти
- доступ на запись проверяется RLS по `app_metadata.role = "admin"`, а не по клиентской проверке
- `saveEvent()` — создание/редактирование события
- `deleteEvent()` — удаление события
- `renderEvents()` — список событий
- При включённом «Повторять ежегодно» событие сохраняется с `recurrence: "yearly"`; День рождения БХЧ уже настроен как ежегодное событие
- `downloadEventsJson()` / `importEventsJson()` — экспорт/импорт JSON
- `saveBirthday()` / `editBirthday()` / `deleteBirthday()` — управление днями рождения
- дни рождения синхронизируются с Supabase; старый локальный черновик `buhlo_birthdays_admin_draft` сохраняется и может быть импортирован вручную
- импорт/экспорт используют объект `{ "birthdays": [{ "date": "YYYY-MM-DD", "name": "..." }] }`
- `saveHoliday()` / `editHoliday()` / `deleteHoliday()` — управление праздниками с датой `MM-DD` и типом `general` или `moto`
- праздники синхронизируются с Supabase; старый локальный черновик `buhlo_holidays_admin_draft` сохраняется и может быть импортирован вручную
- импорт/экспорт работают с объектом `{ "holidays": [{ "date": "MM-DD", "name": "...", "event_type": "general|moto" }] }`
- `changeAdminPassword()` — смена пароля
- `loadEventsFromServer()` — повторная загрузка событий из Supabase; CRUD и JSON-импорт записывают изменения сразу

## Данные
- События загружаются из Supabase и кэшируются в `localStorage` как массив объектов:
  - `id`
  - `title`
  - `date`
  - `time`
  - `location`
  - `description`
  - `participants[]`
  - `maxParticipants`
  - необязательное `recurrence: "yearly"` для ежегодного события
- Регистрация хранится в Supabase; `REGISTRATIONS_KEY` содержит только локальную отметку/ключ дедупликации.

## Важные особенности
- Для хаба доступ закрыт по вопросу про директора и корректному ответу `Лена`.
- Если при входе выбрана опция запоминания, доступ сохраняется в `localStorage` этого браузера; для сброса нужно удалить ключ `buhlo_hub_authenticated`.
- Админский Auth токен не записывается в localStorage/cookies; Supabase проверяет права через RLS.
- Публичные участники видят только имена; контакты и комментарии к регистрации доступны только администраторам.
- `js/supabase-config.js` содержит URL проекта и публичный anon/publishable key. Никогда не помещай туда service-role key. Публичный ключ не позволил прочитать `event_registrations`, что соответствует ожидаемому ограничению доступа.
- В проекте есть два ключевых события: Пятничный сбор и выезд на Нёман.

## Навыки для ускорения работы

Используй эти короткие сценарии при изменениях, чтобы быстрее находить связанные места и не пропускать важные поверхности:

### 1. Навигация по функциональности
- Главная страница: сначала найди элемент по `id` в `index.html`, затем обработчик и рендер в `js/main.js`, после этого связанные стили в `css/styles.css` или `css/upcoming.css`.
- Админка: проверь `pages/admin.html`, соответствующую функцию в `js/admin.js` и `css/admin.css`.
- Для поведения ищи существующие функции (`loadEvents()`, `renderEvents()`, `submitRegistration()` и другие из раздела выше) и расширяй их вместо добавления параллельной логики.

### 2. Быстрое изменение данных
- События: в обычном режиме база Supabase — общий источник данных; `data/events.json` используется как fallback и для первичного импорта. JSON поддерживает массив или объект с массивом `events`.
- Дни рождения: `data/birthdays.json` содержит объект `birthdays` с элементами `{ "date": "YYYY-MM-DD", "name": "..." }`.
- Праздники: `data/holidays.json` содержит объект `holidays`; дата задаётся как `MM-DD`.
- В админке можно выгрузить резервные JSON-файлы. Локальные черновики прошлой версии сохраняются до явного импорта в Supabase.
- При изменении формата проверь одновременно загрузчик, отображение и данные в `localStorage`: локальная копия может перекрыть ожидаемый результат.

### 3. Поиск причин неисправности
- Сначала проверь ошибки в консоли браузера и Network: загрузились ли HTML, JS и JSON без ошибок.
- Сверь относительные URL: главная загружает данные относительно корня, админка — относительно `pages/`.
- Для проблем с отображением проверь, что `id`/классы в HTML совпадают с селекторами и что нужный CSS подключён.
- Если мешают устаревшие данные, очисти только соответствующий ключ `localStorage` (`buhlo_events_data`, `buhlo_birthdays_data` или `buhlo_holidays_data`), а не всё хранилище.

### 4. Безопасные изменения доступа и синхронизации
- Не добавляй пароли, токены и ответы на контрольные вопросы в документацию, коммиты или клиентский код.
- Любое значение в HTML/JavaScript доступно пользователю; реальную авторизацию проверяют Supabase Auth и RLS, а не код страницы.
- Публичный Supabase key допустим в браузере только при настроенных ограничительных RLS policies; service-role key запрещён во frontend.

### 5. Подключение Supabase
- Обновлённый `supabase/schema.sql` добавляет в `public.events` столбцы `event_id` (уникальный, автоинкремент, заполняется из `id`), `time`, `"maxParticipants"`; `events.id` остаётся собственным автоинкрементным ключом без внешних связей. Запусти скрипт в SQL Editor.
- В существующей базе был FK `events_id_fkey`: `events.id → event_registrations.id` (мешал сохранять события). Скрипт снимает его и любые связи регистраций с событиями, переносит подходящие старые `id` регистраций в новый `event_id` (FK на `events.event_id`), а `id` делает собственным автоинкрементным ключом. Регистрации без подходящего события остаются с `event_id = NULL`. Также `events.recurrence` становится nullable.
- В `js/supabase-config.js` укажи публичный anon/publishable key из Supabase Settings → API Keys; service-role key не используй.
- Создай пользователя в Supabase Auth, затем присвой ему `app_metadata.role = "admin"` (через Dashboard/SQL Editor, не `user_metadata`) и войди в админку заново.
- После применения схемы импортируй через админку `data/events.json`, `data/birthdays.json` и `data/holidays.json`, если нужно загрузить опубликованные данные в базу.
- Настрой URLs для Supabase Auth (Site URL и Redirect URLs) на адрес GitHub Pages.
- Публичная регистрация использует SQL-функцию, которая атомарно проверяет лимит мест; посетителям возвращаются только имена. Контакт и комментарий остаются закрытыми.

### 6. Подготовка публикации
- В проекте нет отдельной сборки: GitHub Actions публикует содержимое репозитория на GitHub Pages при push в `main`.
- Перед публикацией проверь JSON на синтаксические ошибки, ссылки и относительные пути, затем открой главную и админку в браузере.
- Просмотри итоговый diff и убедись, что в нём нет случайных файлов IDE, локальных данных или секретов.

## Состояние Supabase
- Через публичный API подтверждены доступные `public.events`, `public.birthdays`, `public.holidays`; `public.event_registrations` не читается анонимной ролью.
- В `public.events` REST API подтвердил `id`, `title`, `date`, `location`, `description`, `recurrence`. Запрос событий на момент проверки вернул пустой массив. Отсутствуют `time` и `"maxParticipants"` — их добавляет обновлённый `supabase/schema.sql`.
- `js/supabase.js` обращается к REST-ресурсу `events` и использует `event_id` для получения, сохранения (`on_conflict=event_id`) и удаления событий. `event_registrations.event_id` ссылается на `events.event_id`.
- `supabase/schema.sql`: `events.id` — собственный автоинкрементный ключ без связей; `events.event_id` — уникальный ключ приложения; в `event_registrations` связь `id → events.id` заменяется на отдельный `event_id` с FK, старые записи переносятся.
