# Release_A1 Проект — Справка

## Описание
**БУХЛОЧАТ** — официальный хаб для встреч, событий и общих выездов. Это клиентское JS-приложение с простой авторизацией, админ-кабинетом и таймером до поездки на Нёман.

## Стек
- Язык: JavaScript, HTML, CSS
- Архитектура: vanilla JS, static site, localStorage-based state
- Дополнительно: fetch для `data/events.json`, опциональный API proxy через `window.BUHLO_API_URL`

## Последние обновления
- Данные событий, дней рождения и праздников загружаются из JSON-файлов и могут кэшироваться в `localStorage`
- Проверка доступа реализована на клиенте; значения в JavaScript доступны посетителям и не являются защитой для секретов
- Исправлен `data/birthdays.json`: теперь данные обёрнуты в объект `{"birthdays": [...]}` с полями `date` (YYYY-MM-DD) и `name` — `loadBirthdays()` в `js/main.js` корректно читает и отображает дни рождения
- В день рождения по списку запускается кратковременная анимация падающих шариков и лент; эффект отключён при `prefers-reduced-motion`
- В блоке «Галерея выездов» отображается фотография `gallery/Lida.jpg`; изображение адаптивно подстраивается под ширину карточки
- Прошедшие разовые события скрываются после завершения календарного дня; события с `recurrence: "yearly"` показываются с календарной даты за месяц до годовщины и скрываются со следующего дня
- Таймер до Нёмана обновлён и оформлен как крупный neon-style countdown
- Основной стиль страницы обновлён: более чистый dark UI, акцентные цвета, glow-эффекты, улучшенные карточки и кнопки
- Авторизационный экран разделён визуально и выглядит как отдельный входной блок

## Основные сценарии

### Главная страница (`index.html`)
- блок `auth-overlay` с контрольным вопросом и входом в хаб
- опция «Запомнить меня на этом устройстве» сохраняет доступ в браузере через `buhlo_hub_authenticated`
- доступ на главный контент только после корректного ответа `Лена`
- фото `gallery/Lida.jpg` отображается в блоке «Галерея выездов»; новые фото нужно положить в `gallery/` и указать путь в HTML
- меню разделов: события, таймер, встречи, алкометр, контакты, дни рождения
- загрузка `js/main.js` на старте

### Логика главной (`js/main.js`)
- `HUB_ANSWER = 'лена'` — корректный ответ для входа в хаб
- `EVENTS_KEY = 'buhlo_events_data'` — ключ событий в localStorage
- `REGISTRATIONS_KEY = 'buhlo_registrations'` — ключ регистраций на события
- `checkAuth()` — проверка входа в хаб
- `initPage()` — инициализация таймера, калькулятора и событий
- `startTimer()` — обратный отсчет до даты `buhlo_target_date`
- `calculateAlcohol()` — расчет закупки алкоголя
- `loadEvents()` — загрузка данных из localStorage или `data/events.json`
- `loadBirthdays()` — загрузка дней рождения из `data/birthdays.json`, отображение в `bdays-sec` и запуск праздничной анимации при совпадении даты
- `submitRegistration(eventId)` — регистрация на событие

### Админка (`pages/admin.html` + `js/admin.js`)
- проверка пароля выполняется в браузере; `simpleDecrypt()` — только обфускация, не шифрование
- авторизация хранится только в памяти страницы (`isAdminAuthenticated`)
- `saveEvent()` — создание/редактирование события
- `deleteEvent()` — удаление события
- `renderEvents()` — список событий
- При включённом «Повторять ежегодно» событие сохраняется с `recurrence: "yearly"`; День рождения БХЧ уже настроен как ежегодное событие
- `downloadEventsJson()` / `importEventsJson()` — экспорт/импорт JSON
- `saveBirthday()` / `editBirthday()` / `deleteBirthday()` — управление днями рождения
- локальный черновик дней рождения хранится в `buhlo_birthdays_admin_draft`; экспортируй его в `birthdays.json`, чтобы вручную добавить файл в `data/` и задеплоить сайт
- импорт/экспорт используют объект `{ "birthdays": [{ "date": "YYYY-MM-DD", "name": "..." }] }`; при настроенном proxy используются маршруты `/birthdays`
- `saveHoliday()` / `editHoliday()` / `deleteHoliday()` — управление праздниками с датой `MM-DD` и типом `general` или `moto`
- локальный черновик праздников хранится в `buhlo_holidays_admin_draft`; скачай `holidays.json`, чтобы вручную обновить файл `data/holidays.json` и задеплоить сайт
- админка загружает черновик праздников, если он есть, иначе читает опубликованный `data/holidays.json`; импорт/экспорт работают с объектом `{ "holidays": [{ "date": "MM-DD", "name": "...", "event_type": "general|moto" }] }`
- `changeAdminPassword()` — смена пароля
- `saveEventsToServer()` / `loadEventsFromServer()` — синхронизация через API, если `window.BUHLO_API_URL` задан

## Данные
- События хранятся в `localStorage` как массив объектов:
  - `id`
  - `title`
  - `date`
  - `time`
  - `location`
  - `description`
  - `participants[]`
  - `maxParticipants`
  - необязательное `recurrence: "yearly"` для ежегодного события
- Регистрация пользователя на событие хранится отдельно в `REGISTRATIONS_KEY`.

## Важные особенности
- Для хаба доступ закрыт по вопросу про директора и корректному ответу `Лена`.
- Если при входе выбрана опция запоминания, доступ сохраняется в `localStorage` этого браузера; для сброса нужно удалить ключ `buhlo_hub_authenticated`.
- Для админки используется отдельный пароль, скрытый/зашифрованный в коде.
- Проект работает без серверного backend по умолчанию; всё хранится в browser storage.
- Для серверной синхронизации нужен внешний proxy, а не прямой доступ к GitHub token из браузера.
- В проекте есть два ключевых события: Пятничный сбор и выезд на Нёман.

## Навыки для ускорения работы

Используй эти короткие сценарии при изменениях, чтобы быстрее находить связанные места и не пропускать важные поверхности:

### 1. Навигация по функциональности
- Главная страница: сначала найди элемент по `id` в `index.html`, затем обработчик и рендер в `js/main.js`, после этого связанные стили в `css/styles.css` или `css/upcoming.css`.
- Админка: проверь `pages/admin.html`, соответствующую функцию в `js/admin.js` и `css/admin.css`.
- Для поведения ищи существующие функции (`loadEvents()`, `renderEvents()`, `submitRegistration()` и другие из раздела выше) и расширяй их вместо добавления параллельной логики.

### 2. Быстрое изменение данных
- События: редактируй `data/events.json`; поддерживаемая структура — массив или объект с массивом `events`. Сохраняй поля события: `id`, `title`, `date`, `time`, `location`, `description`, `participants`, `maxParticipants`.
- Дни рождения: `data/birthdays.json` содержит объект `birthdays` с элементами `{ "date": "YYYY-MM-DD", "name": "..." }`.
- Праздники: `data/holidays.json` содержит объект `holidays`; дата задаётся как `MM-DD`.
- В админке можно скачать текущий опубликованный `data/holidays.json` кнопкой «Скачать holidays.json»; локального черновика праздников нет.
- При изменении формата проверь одновременно загрузчик, отображение и данные в `localStorage`: локальная копия может перекрыть ожидаемый результат.

### 3. Поиск причин неисправности
- Сначала проверь ошибки в консоли браузера и Network: загрузились ли HTML, JS и JSON без ошибок.
- Сверь относительные URL: главная загружает данные относительно корня, админка — относительно `pages/`.
- Для проблем с отображением проверь, что `id`/классы в HTML совпадают с селекторами и что нужный CSS подключён.
- Если мешают устаревшие данные, очисти только соответствующий ключ `localStorage` (`buhlo_events_data`, `buhlo_birthdays_data` или `buhlo_holidays_data`), а не всё хранилище.

### 4. Безопасные изменения доступа и синхронизации
- Не добавляй пароли, токены и ответы на контрольные вопросы в документацию, коммиты или клиентский код.
- Любое значение в HTML/JavaScript доступно пользователю; XOR-обфускация не защищает секреты. Реальную авторизацию и секреты переноси на сервер.
- Для синхронизации с GitHub используй только серверный proxy через `window.BUHLO_API_URL`; не помещай GitHub token во frontend.

### 5. Подготовка публикации
- В проекте нет отдельной сборки: GitHub Actions публикует содержимое репозитория на GitHub Pages при push в `main`.
- Перед публикацией проверь JSON на синтаксические ошибки, ссылки и относительные пути, затем открой главную и админку в браузере.
- Просмотри итоговый diff и убедись, что в нём нет случайных файлов IDE, локальных данных или секретов.
