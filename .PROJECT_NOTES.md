# Release_A1 Проект — Справка

## Описание
**БУХЛОЧАТ** — официальный хаб для встреч, событий и общих выездов. Это клиентское JS-приложение с простой авторизацией, админ-кабинетом и таймером до поездки на Нёман.

## Стек
- Язык: JavaScript, HTML, CSS
- Архитектура: vanilla JS, static site, localStorage-based state
- Дополнительно: fetch для `data/events.json`, опциональный API proxy через `window.BUHLO_API_URL`

## Основные сценарии

### Главная страница (`index.html`)
- блок `auth-overlay` с контрольным вопросом и входом в хаб
- доступ на главный контент только после корректного ответа `Лена`
- меню разделов: события, таймер, встречи, алкометр, контакты, дни рождения
- загрузка `js/main.js` на старте

### Логика главной (`js/main.js`)
- `HUB_ANSWER = 'лена'` — корректный ответ для входа в хаб
- `EVENTS_KEY = 'buhlo_events_data'` — ключ событий в localStorage
- `REGISTRATIONS_KEY = 'buhlo_registrations'` — ключ регистраций на события
- `checkAuth()` — проверка входа в хаб
- `initPage()` — инициализация таймера, калькулятора и событий
- `startTimer()` — обратный отсчет до даты `buhlo_target_date`
- `calculateAlcohol()` — расчет закупки алкоголя
- `loadEvents()` — загрузка данных из localStorage или `data/events.json`
- `loadBirthdays()` — загрузка дней рождения из `data/birthdays.json`, группировка по месяцам и рендер в `bdays-sec`
- `submitRegistration(eventId)` — регистрация на событие

### Админка (`pages/admin.html` + `js/admin.js`)
- пароль admin: `Pvfxbycrbq1981`
- session key: `buhlo_admin_logged_in`
- `saveEvent()` — создание/редактирование события
- `deleteEvent()` — удаление события
- `renderEvents()` — список событий
- `downloadEventsJson()` / `importEventsJson()` — экспорт/импорт JSON
- `changeAdminPassword()` — смена пароля
- `saveEventsToServer()` / `loadEventsFromServer()` — синхронизация через API, если `window.BUHLO_API_URL` задан

## Данные
- События хранятся в `localStorage` как массив объектов:
  - `id`
  - `title`
  - `date`
  - `time`
  - `location`
  - `description`
  - `participants[]`
  - `maxParticipants`
- Регистрация пользователя на событие хранится отдельно в `REGISTRATIONS_KEY`.

## Важные особенности
- Для хаба доступ закрыт по вопросу про директора и корректному ответу `Лена`.
- Для админки используется отдельный пароль, скрытый/зашифрованный в коде.
- Проект работает без серверного backend по умолчанию; всё хранится в browser storage.
- Для серверной синхронизации нужен внешний proxy, а не прямой доступ к GitHub token из браузера.
- В проекте есть два ключевых события: Пятничный сбор и выезд на Нёман.
