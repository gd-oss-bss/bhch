# Промпт: Устранение уязвимостей JS-frontend БУХЛОЧАТ

## Цель
Провести безопасный рефакторинг frontend-приложения `C:/Personal/bhch11`, устранить найденные уязвимости XSS, insecure storage, weak auth UI и file upload, усилить защиту от clickjacking и data leakage.

## Задачи

### 1. Заменить `innerHTML` на безопасный DOM API
- В файлах `js/main.js`, `js/admin.js`, `js/member.js`, `js/stats.js` найти все места, где `innerHTML` заполняется пользовательскими данными (события, дни рождения, праздники, галерея, инфо-посты, статистика).
- Переписать рендеринг через `document.createElement`, `textContent`, `setAttribute`.
- Там, где HTML-шаблонизация необходима, использовать DOMPurify (или аналог) для санитизации.

### 2. Убрать inline-обработчики `onclick="..."`
- Заменить на `addEventListener` + `data-*` атрибуты (`data-event-id`, `data-index` и т.д.).
- Это исключит XSS через кавычки/спецсимволы в ID событий, участников, категорий.

### 3. Защитить хранение сессии
- В `js/supabase.js` убрать сохранение `access_token`/`refresh_token` в `localStorage`.
- Оставить только `sessionStorage` с короткой сессией.
- В идеале — вынести auth в backend-прокси с `httpOnly` cookies.

### 4. Вынести Supabase-конфиг из репозитория
- В `js/supabase-config.js` заменить жёстко зашитый URL и `anonKey` на плейсхолдеры.
- Добавить `.env` / переменные сборки и инструкцию по настройке.
- Предупредить владельца проекта о необходимости ротации `anonKey`.

### 5. Усилить валидацию URL
- В `getHttpUrl()` / `getMemberHttpUrl()` дополнительно отсекать управляющие символы (`\n`, `\r`, `\0`, `\x00-\x1f`).
- Убедиться, что протокол строго `http:` или `https:`.

### 6. Исправить загрузку файлов
- Добавить серверную защиту (bucket policy / RLS Storage) на MIME-тип, расширение и размер.
- Перед `createImageBitmap()` проверять размер файла и ограничивать разрешение/память.
- Использовать полный `crypto.randomUUID()` без `.slice(0, 8)` для имён файлов.

### 7. Каскадное удаление файлов из Storage
- При удалении фото галереи (`deleteGalleryPhoto`) и инфо-поста (`deleteInfoPost`) дополнительно удалять соответствующие файлы из Supabase Storage.
- Использовать `deleteStorageFiles()` для `path` и `thumb_path`.

### 8. Добавить защитные заголовки / CSP
- Добавить `<meta http-equiv="Content-Security-Policy" ...>` в `index.html`, `pages/admin.html`, `pages/member.html`.
- Указать в инструкции по деплою настройку серверных заголовков:
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`

### 9. Убрать production-логи
- Удалить или закомментировать `console.log('Date updated to:', ...)` и `console.log('Tick - Target:', ...)` в `js/main.js`.

### 10. Проверить и ужесточить RLS-политики Supabase
- Убедиться, что участники могут редактировать только свои события (`updateOwnEvent`).
- Убедиться, что удалять/редактировать категории и пользователей могут только администраторы.
- Проверить, что публичный anon key не даёт прав на запись в защищённые таблицы.

### 11. Запустить проверку
- После правок выполнить `npm audit` (если есть `package.json`) или аналог.
- Провести ручное тестирование: попытаться вставить `<script>alert(1)</script>` в название/описание события, день рождения, подпись к фото и убедиться, что скрипт не выполняется.

## Ограничения
- Не менять логику бизнес-процессов (создание событий, регистрация, галерея).
- Не коммитить и не пушить изменения самостоятельно.
- Перед началом работы создать отдельный feature branch.

## Ожидаемый результат
- Все пользовательские данные выводятся без `innerHTML` или проходят санитизацию.
- JWT не хранится в `localStorage`.
- Supabase-конфиг вынесен из кода.
- Файлы удаляются из Storage вместе с записями БД.
- Добавлены CSP и защитные заголовки.
- Приложение проходит базовую XSS-проверку.
